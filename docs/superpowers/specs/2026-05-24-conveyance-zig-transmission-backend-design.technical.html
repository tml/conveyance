Conveyance — Engine Design (Technical)

Hybrid-runtime Zig reimplementation of libtransmission's core, as a JSON-RPC daemon.

Zig 0.14.xio_uring/epoll reactorsingle-mutator session threadJSON-RPC drop-in

Conveyance is a drop-in transmission-daemon replacement written in Zig. It speaks the same JSON-RPC/HTTP protocol and reuses an existing config directory, while fixing the blocking startup load and replacing free-text logging with structured, non-blocking records.

Runtime & threading model

Core invariant: all torrent/peer state is mutated on exactly one thread (the session-owner). Every other thread communicates by message. This mirrors Transmission's run_in_session_thread discipline, made explicit.

Thread / poolResponsibility
Net reactorAll non-blocking socket I/O (peers, trackers, RPC listener); stateless peer-wire framing; owns no torrent state. Accepts RPC at startup before any torrent loads.
Session-ownerSingle mutator of the torrent registry; drains one MPSC command/event queue; periodic tick (announces, choke rotation, stats, resume persist).
Loader poolOne job per .torrent: parse metainfo + import .resume → post TorrentLoaded. Reused for torrent-add.
Disk/hash poolSHA-1 piece verification, block read/write, preallocation.
LoggerDrains a bounded MPSC ring; producers never block (full → dropped-counter).

Startup streaming load (the pain-point fix)

The session thread enumerates torrents/*.torrent, submits one loader job each, and returns immediately — no future.get() barrier. Each torrent is registered and made live the instant its parse completes; a malformed file is logged and skipped without blocking the rest.

State compatibility

Read: settings.json, torrents/*.torrent (untouched), resume/*.resume (bencode → imported). Write: our own JSON sidecars under a new conveyance/ subdir; we never overwrite transmission's resume/, so reverting to the C++ daemon is safe.

RPC surface (v1)

JSON-RPC over HTTP, CSRF-guarded by X-Transmission-Session-Id (409 + header when missing). Methods: session-get/-set/-stats, torrent-get/-add/-start/-stop/ -remove/-verify/-set, free-space. Reports matching rpc-version/rpc-version-minimum.

Errors, resources, testing

  • Zig error unions throughout; no steady-state panics. Per-torrent load failures isolated.
  • Arena allocator per load-job / per RPC request; long-lived state in a GPA.
  • TDD: unit tests for parsers against fixtures; golden RPC tests vs. a real daemon; a concurrency test asserting torrents appear individually and one bad file doesn't block others; an end-to-end download against a local seed + tracker.
