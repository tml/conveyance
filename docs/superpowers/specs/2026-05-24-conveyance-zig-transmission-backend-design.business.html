Conveyance — Project Overview

A faster, more transparent drop-in replacement for the Transmission download engine.

Drop-in for transmission-daemonLinux-firstReuses existing GUIs & web UI

Conveyance reimplements the core engine behind Transmission (the popular BitTorrent app) in a modern systems language, packaged so the apps and web UI people already use keep working unchanged. It targets two everyday frustrations.

Win #1 — No startup stall. Today, when the service restarts it freezes until it has re-read every torrent from disk, one after another. With many torrents that is a long, opaque wait. Conveyance lets each torrent become usable the moment it is read, and answers clients immediately.
Win #2 — Logs you can actually use. Modern, structured logs tagged with which torrent and which part of the system produced them — searchable and feedable to monitoring tools, instead of free-text lines.

Before vs. after: the startup experience

What stays compatible

  • Talks the same remote-control protocol — the existing web UI, transmission-remote, and remote-mode desktop apps connect with no changes.
  • Reads your existing data (torrents and saved progress) so switching over does not start from scratch.
  • Writes its own progress files separately, so you can switch back to the original app safely.

How it will be delivered

The full engine is large, so it ships in stages. The first finished product downloads a torrent end-to-end with the two wins above built in; later stages add the remaining networking features.

StageWhat it delivers
M0 — FoundationProject skeleton, the new logging system, and the file readers everything builds on.
M1 — Live serviceThe service starts, answers clients immediately, and shows torrents appearing as they load. This is where the startup win is visible.
M2 — TrackersFinds peers; torrents show real peer counts.
M3 — DownloadingConnects to peers and downloads a torrent to completion.
M4 — PersistenceRemembers progress across restarts; start/stop/remove/verify controls.

Scope of the first release

To keep the first release achievable, some advanced networking is intentionally deferred (encryption, peer discovery via DHT, and a few transfer optimizations). These are planned for later sub-projects. The first release focuses on the core download path plus the startup and logging improvements.
